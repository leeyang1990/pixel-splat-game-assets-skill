# 3D 像素高斯游戏资产制作

目标是把参考所体现的完成度转化为可重复执行的制作标准，并生产符合该标准的独立游戏资产。从参考中提取品质与风格，使用原创造型或用户有权复用的资产与关卡布局。更换主题时保留适用的品质标准，重新设计形体、材质和装饰。

```text
参考图／对话 → 品质目标与游戏约束
→ 代表资产 → 原始高斯、目标游戏尺寸和适用视角的检查
→ 定位差距、回修造型／材质／照明／采样／出图
→ 验证后固定制作规则 → 扩展资产族并检查组合
→ 独立资产、生成源码、动画交互适配与验证证据
```

最终可见的三维美术均由真实 Gaussian splats 构成。中间造型可使用精细网格、程序化表面、雕刻或 SDF；运行时绘制高斯投影与衰减。碰撞体、界面和调试线独立。程序化生成无需照片训练。

## 1. 把输入转化为品质目标

先读 [品质目标与生产决策](references/quality-production.md)，实际查看参考图／视频帧，或将对话落实为美术说明。记录最终镜头、资产在游戏中的像素尺寸、需要读清的特征、造型层次、材质色阶、光照关系与适用状态。不要只记录“精致、像素风”等形容词。

可用 [输入模板](assets/brief.template.json) 的 `quality` 字段，或沿用项目已有记录；由 agent 填写，不要求用户先填表。方向足够时直接制作，只询问阻断交付的信息，不增加固定方向选择或审批环节。没有画面参考时先定义可检查的目标，不虚构已与外部品质标杆对齐。

检查项目已有渲染、坐标、加载和玩法接口，复用兼容的 Gaussian renderer；没有环境时使用随包 WebGL2 运行模块。兼容标准见 [渲染与接入](references/representations.md)。技术选型由造型、画质和接入要求决定，不为采用某篇教程更换引擎，也不把 SDF、四采样或描边当作画质达标的充分条件。

统一单位、原点、材质／色阶、采样与像素约定。无现有约定时默认 +Y 向上、+Z 朝前、一格 1 单位；道具用底部中心，地形用可行走顶面中心，挂载构件用明确挂点。记录实际支撑高度、同屏实例和设备预算，未实测的性能标为未测。

## 2. 代表资产与画质回修

按 [精细造型与视觉验收](references/high-fidelity.md) 制作能暴露主要品质风险的代表资产；用户指定了先做的样件时遵照其范围，没有统一的最低数量。优先解决轮廓、比例、中等尺度结构、材质组织与明暗，再分配细节和高斯密度。

建筑、复杂植被和分层地形同场时，读 [精细环境资产的制作与验收](references/layered-environments.md)。按三种尺度设计结构，用单件斜视、实际游戏尺寸和拼装场景定位差距，再处理细采样与出图。

实际加载导出的二进制，在原始高斯、目标游戏尺寸及适用的旋转／状态下检查，并放入最小组合验证场。保存相机、时间、造型／风格配置及可比较图像。将数据、画质、复用／行为结论分别记录；失败或未检查的关键品质项保留为待改，不能用数量、滤镜、文件检查或平均分覆盖。

按差距修改负责的环节，再检查受影响画面。样件未达到目标时继续校准样件，保持该批量扩展任务待完成；不通过增加同类资产数量结束画质任务。遇到实际工具限制时说明缺口和当前产物范围，不把工程起点描述为已经达到参考品质。

通过后保留样件数据／哈希、生成配置、材质规则、显示设置和证据，作为当前项目后续资产的校准基准。样件通过只覆盖已验证的类别、视角与状态；新增类别和透明／动态效果需检查其自身风险。随包 starter 和历史样例用于接通接口，不自动充当品质基准。

## 3. 选择制作方法并生成高斯

实现时读 [高斯生成流程](references/gaussian-pipeline.md)，按需读 [资产类别](references/asset-families.md)。形体与材质先满足品质目标，再选择合适入口：

- 距离函数适合能清楚程序描述的形体，见 [SDF 直接采样](references/sdf-route.md) 与 `assets/sdf-to-gaussians/`；不为减少步骤而删掉识别性结构。
- 精细表面、既有模型、雕刻或复杂材质可走表面转换，见 [精细造型](references/high-fidelity.md) 与 `assets/mesh-to-gaussians/`。同一资产族可混用入口，共用导出和风格约定。

采样输出位置、三个正标准差、单位旋转、颜色和透明度。密度按轮廓、表面覆盖和细线需要分配，切向尺度与法向厚度分开；检查孔洞、越界拖影与量化后的 3σ 范围。共享采样、材质和独立随机源，种子不依赖资产生成顺序。

固定灯光展示可预烘焙材质色阶；会旋转、换灯或动作的资产按用途保留反照率、局部遮蔽和法线，由已实现的世界照明处理。局部 AO 不等于完整场景光照，烘焙颜色也不能重复叠加同一套灯。透明水、雾和光束单独处理，不全局套用实心覆盖阈值。

按 [v2 资产约定](references/asset-contract.md) 导出独立 `.splat`、可编辑 JSON、原点、边界和适用的碰撞／挂点／部件信息。定义与实例分开，静态数据缓存复用，游戏帧循环不重新生成资产。

## 4. 像素出图与游戏组合

按 [像素出图与同帧对比](references/pixel-output.md) 校准已确定的游戏像素预算。原始高斯应已包含成立的形体、材质和明暗；最终网格、限色、轮廓、抖动或泛光按目标选择，不把滤镜叠加当成细节制作。统一网格和保护细窗格／叶片的分层网格均可使用，准确标注实际规则。

纯后处理对比共用同一张冻结场景帧。改变高斯覆盖阈值时固定几何、相机、时间并记录两次绘制参数，不声称输入 RGBA 相同。明确区分渲染抗锯齿采样、后续像素合并与整数放大；CPU 导出通过不代表实时游戏性能。

将同一批独立文件重复摆放、旋转、拼接或挂载，检查尺度、边界、接缝、碰撞和风格一致性。单件品质与场景构图、灯光、透明效果分别检查；展示台、布景和特效保持可拆分，不把整场焊成单件来获得成片效果。

多场景交付时，按 [多场景资产生产与验收](references/scene-packs.md) 共享导出和运行约定。逐场景保存配色、镜头、摆放、原始／像素同帧图和针对主要风险的单件验证。高级运行模块的场景可用 `scripts/check_scene.py manifest.json scene.json` 检查资产引用、实例变换和总实例高斯数。

场景含动态水面、体积光、多部件人物或大量实例时，读 [场景材质与动画](references/scene-runtime.md)，按需复用 `assets/advanced-runtime/`。`.splat` 保存静止姿态；部件变换、动画片段、碰撞与交互由适配器／控制器实现并测试，只写元数据不代表能动或能交互。

## 5. 运行起点与交付

新建工程可选择 `assets/starter/` 接通生成、二进制加载和验证场；扩充现有项目时直接接入，不必重建展示工程。starter 是正交投影、预烘焙 RGB 的工程样例，不含训练或视角相关 SH。高级运行模块提供 GPU 投影、水面镜像、部件变换和特效池，仍需制作当前任务的造型与行为。

starter 使用 Node 内置模块和 Python 静态服务：

```sh
node src/generate.mjs
python3 -m http.server 8000 --bind 127.0.0.1
node tests/validate.mjs
python3 <skill-dir>/scripts/check_manifest.py manifest.json
```

按实际项目替换路径与生成命令；SDF／精细表面的命令见对应参考。Python 检查器只验证数据与元数据，画质、渲染执行和行为另行验证。基础 starter 用 `style.palette` 与角度制相机，高级模块用 `style.colors` 与弧度相机，先读项目 schema。

交付独立资产、编辑数据、造型生成器、共享风格／清单、必要运行适配、最小复用验证场和准确启动命令。附品质目标、实际视觉证据、剩余差距及验证范围；注明目标尺寸和视角，不将有限样件通过外推为所有主题、动画或设备的保证。

后续扩展复用当前项目已经验证的形体层次、材质和转换规则；反馈定位到受影响环节后修改并复查，再继续生产。
