# 像素出图与同帧对比

适用于调试两个模式、明确像素感或保护窗棂、叶片等细节。出图处理发生在真实高斯合成之后；不更换场景数据或以参考贴图代替渲染。

## 两个模式的边界

原始模式显示同一场景的完整分辨率帧，只作必要的拷贝。高斯材质、照明和水面反射仍属于场景；成片泛光、限色、抖动、细节重采样全部绕过。不要给原始模式保留与成片相同的泛光。

像素模式明确配置逻辑网格／色块尺度、显示色板和可选抖动。先检查实际尺寸：若目标高度大于窗口，而两边又都关闭限色、抖动，按钮可能几乎没有视觉作用。校准阶段关闭后处理是合理的，交付前必须恢复并实际验证所选成片配置。

`assets/advanced-runtime/pixel-display.mjs` 提供整数色块布局、原始拷贝、像素重采样、限色及细节合成着色器。高级渲染器先在完整分辨率生成场景帧，之后制作像素视图；不能把色块分辨率说成整个几何渲染的分辨率。`pixelArt.height` 为粗色块目标高度，`minScale` 为最小整数色块倍率（1–8）；布局会记录边缘余数。默认参数示意：

```js
pixelArt: {
  height: 300, minScale: 2, paletteEnabled: true,
  ditherStrength: 0, detailBias: .65, bloomStrength: .08,
  palette: themePalette // 1–64 个 #RRGGBB 颜色
}
```

尺寸、颜色数和强度按当前美术校准，不把这个示意作为所有主题的标准。抖动并非像素感的必要条件；它可能破坏细线、叶片和运动稳定性。

## 保护关键细节

先检查关键特征在目标尺寸下有多少像素。统一低分辨率无法完整保留小于其网格的细节；提高逻辑分辨率或重新安排造型／显示尺度，均是合理选择。

需要同时保留粗大色块和精细窗格／植被时，高级模块支持分层像素网格。未标注的大面使用较粗整数色块；`foliage` 材质和资产 `pixelDetailRanges:[{start,count}]` 在原生像素网格上取源帧颜色，再映射到同一色板。区间单位为高斯记录，可稀疏但须合法且不重叠；由造型／材质语义指定，不依赖截图颜色猜测。二进制 `.splat` 不编码这些区间，复用时带上清单。

材质覆盖蒙版随真实高斯、遮挡和透明度一起合成，不能直接把原始高分辨率图以半透明方式盖回来。细部也应有离散色阶。只标注需要保留的构件，观察整体仍有清楚像素感。此模式是“粗色块 + 细像素”，不要宣称整幅图严格统一为同一种放大倍率。

色板也可能抹掉细节。整幅图一次自动量化容易让背景、石墙占据颜色配额，使绿色叶片灰暗或亮饰与玻璃混色。按代表材质检查并分配深浅色阶，保证植物、玻璃亮部、石材、暖灯及人物的识别色各有足够覆盖。具体配额、颜色提取规则属于项目美术；不将绿色植物的规则用于其他主题。

## 同帧证据

先暂停场景时间和控制器／动画，保留镜头、姿态、风、水波和灯光。先渲染一次场景，再由同一纹理导出两个视图，不分别推进两次游戏帧。

这项同源要求用于隔离后处理的影响。[实心像素风支路](sdf-route.md) 可另用非零 `alphaCut` 改变高斯覆盖；此时连续高斯与实心绘制共用冻结的几何、镜头和时间，但并非同一张 RGBA 源帧。应记录两组覆盖参数，再从同一张实心源帧比较“仅限色”与“加同色轮廓”，将两种影响分别验证。

```js
renderer.render(camera, frozenSeconds, frozenPoses);
const pair = renderer.captureComparison();
// pair.raw / pair.pixel / pair.detailsMask 为 PNG data URL
// pair.metadata 包含相同源帧、时间、镜头、尺寸、配置及原始回读指纹
```

调用方另存控制器位置／朝向、动作片段和时间、特效状态等项目上下文。`rawMatchesSource` 检查拷贝后的像素与场景帧回读一致。PNG 可进一步独立回读验证；元数据声明不能替代可见图像与数据检查。

以相同裁切、相同最近邻倍率查看原生图及关键细节。对比图的放大标注与实际倍率一致。确认网格和色阶明显，同时窗格仍形成可追踪的线网、叶簇保留明暗／间隙和背景分离。循环切换后重新导出，暂停帧应保持相同像素。若使用细节蒙版，检查非细节区域的整数色块、细节区域的源颜色限色与蒙版范围，不能对整幅图强行断言所有色块同大。

记录实际验证的视角、显示尺寸、帧与配置；静态截图通过不自动证明所有设备、镜头或运动稳定性。
